# Выпуск 0.5: обозначения, привязки и проверка

Модель Kimi K3 и подготовка PDF прежние: high, максимум 50 000 токенов генерации, один запрос, OCR отключён. Изменились контракт ответа, системная инструкция, локальные проверки и просмотр результата. Это ещё не полный контракт построения CAD.

## Контракт 0.2.0-draft

| Блок | Назначение |
| --- | --- |
| `drawing_general` | Материал, единицы, обозначение, примечания, ссылки на общие требования. |
| `views` | Виды, разрезы и объяснение их взаимного соответствия. |
| `observations` | Прочитанные надписи без исправления чисел/регистра; варианты чтения, вид и координаты источника. |
| `dimensions` | Значения размеров, направление, границы измерения, ссылки на наблюдения. Различаются `read`, `derived`, `assumed`, `unknown`. |
| `requirements` | Единый реестр местных и общих требований: шероховатость, допуски, IT, обработка и прочее. |
| `surfaces` | Физические поверхности, границы, ориентация и неопределённости. |
| `bindings` | Единственное место связи размеров/требований с поверхностями через ID. Обоснование, альтернативы, статус `proposed` или `disputed`. |
| `dimension_chains` | Явно заданные линейные равенства размеров. |
| `validation` | Результат независимых проверок приложения; модель этот блок не заполняет. |

Координаты `evidence.bbox` нормированы к полному отображаемому листу, от верхнего левого угла. Неизвестная область — `null`. Общие требования хранятся один раз в `requirements`, перечислены в `drawing_general.general_requirement_ids`, а применимость к поверхности отражается в `bindings` с объяснением области действия. Количество записей не подтверждает полноту.

У требования `dimension_ids` привязывает IT и размерные отклонения к конкретным размерам. `physical_role` отличает крайний торец, уступ, стенку и дно паза. `bindings.target_evidence` показывает место контакта выноски с контуром или границы измерения; это отдельный источник от самой надписи. Отсутствие этих координат явно отмечается.

Новая исполняемая схема: `schemas/drawing-analysis.schema.json`. Предыдущая сохранена в `schemas/drawing-analysis-0.1.schema.json`; старые пользовательские JSON не переписываются. Импорт старых результатов в приложение не добавлен.

## Проверки приложения

Неверная структура, повторяющиеся ID, несуществующие ссылки, неправильный номер листа/границы области и число при `basis=unknown` не принимаются как результат. После этого приложение формирует замечания:

- Обозначение без трактовки, факт без поверхности, факт без источника, источник без координат.
- Разные прочтения, спорные привязки и отсутствие обоснования.
- Поле допуска без отдельного требования с IT, угол в единицах длины, группировка нескольких физических поверхностей в одной записи.
- Конфликт роли/направления размера с привязкой; конкурирующие размеры одной поверхности.
- Для осевых длин сравнивается полный набор границ: расстояния с одним общим торцом и разными вторыми торцами не считаются конфликтом.
- Разные местные значения одного параметра шероховатости на одной поверхности; общее правило с местным исключением и разные параметры Ra/Rz не считаются таким конфликтом.
- Арифметика явно заданных цепей и вычислений; несовместимые/неизвестные единицы, предположенные значения и циклы.
- Возможные дубликаты поверхностей при совпадении типа, ссылок на размеры и области источника. Автоматического объединения нет.

`error` — обнаруженное противоречие, `warning` — повод для проверки, `not_checkable` — проверка невозможна или не выполнялась, `info` — результат арифметики. Нет статуса «геометрия проверена». Совпадение суммы не доказывает совпадение физических границ. Противоречия сохраняются вместе с исходными данными, значения автоматически не меняются. При экспорте `validation` вычисляется заново и не доверяет присланному из интерфейса вердикту.

## Интерфейс

В панели результатов доступны «Детали», «Обозначения» и «Проверки». Реестр показывает исходное чтение отдельно от трактовки и привязки; есть поиск и список фактов без привязки. Кнопка источника открывает нужный лист PDF и подсвечивает область; при отсутствии координат открывается только лист с явной пометкой. Новое системное указание полностью доступно в отдельном окне «Системный промпт».

## Повторение испытаний

Обычные Rust-тесты и сборка интерфейса не обращаются к Kimi. `tools/test-analysis-ui.cjs` проверяет интерфейс на многостраничном PDF, подменяя только IPC (включая анализ и сохранение); все внешние обращения к модели исключены. Требуются Playwright и установленный Edge (в среде разработки используется комплект Codex через `NODE_PATH`). Запуск: открыть `tools/ui.ps1 -Mode preview`, затем передать скрипту путь PDF с двумя или более листами и сохранённый отчёт 0.5. Тест изменяет копию данных только в памяти, проверяет переход на второй лист, подсветку, масштаб, отсутствие координат, буквальное отображение HTML, проверки и экспорт через подменённую команду.

Платный испытательный тест включается явно через `KIMI_ACCEPTANCE_FILE`, `KIMI_ACCEPTANCE_NAME`, уникальный `KIMI_ACCEPTANCE_RUN` и `cargo test --offline --lib compare_prepared_drawing_with_saved_key -- --ignored --nocapture`. Каждый прогон сохраняет отдельный результат/ошибку и снимок промпта, схемы, настроек. Старые прогоны не перезаписываются. В тестовом режиме также сохраняется финальный ответ с метриками, в том числе при ошибке схемы; рассуждения и ключ не сохраняются. В обычном приложении такой записи нет. Производственные исходники и результаты испытаний находятся в игнорируемой `.local`, в GitHub не отправляются.

В `AnalysisReport.tokenUsage` сохраняется статистика токенов, если API её вернул. Это численные метрики поставщика, не текст рассуждений; отсутствие поля не означает нулевого расхода. Старые отчёты содержат только `totalTokens`.

`status=needs_review`, `ready_for_3d=false` сохраняются всегда. Поэтапный анализ несколькими запросами относится к 0.6.

## Ограничение сетевого потока

Поток SSE ограничен 32 МиБ; это счётчик полученных байтов со служебными JSON-обёртками, весь поток не хранится в памяти. Итоговый JSON по-прежнему ограничен 1 МиБ, отдельная запись — 256 КиБ, генерация — 50 000 токенов, время — 15 минут. Эти три ограничения размера имеют разные сообщения об ошибке. Тест с более чем 8 МиБ отбрасываемого текста рассуждений подтверждает, что лимит итогового JSON не расходуется на служебный поток.

## Испытания 11 октября 2026

Три разрешённых запроса на одном чертеже вала, с неизменным подготовленным пакетом и настройками Kimi:

| Попытка | Результат | Время | Всего токенов |
| --- | --- | --- | --- |
| 1, первоначальная 0.5 | Принят JSON; затем уточнены общие правила промпта и контракт | 8:09 | 78 325 |
| 2, уточнённые правила | `response_too_large`, готового JSON нет | 13:23, время теста | API не вернул статистику |
| 3, тот же промпт и схема, исправленный приём потока | Принят JSON | 8:56 | 84 272 |

В третьей попытке API сообщил 58 503 входных и 25 769 выходных токенов. Вторая ошибка не позволяет задним числом отличить срабатывание прежнего общего порога 8 МиБ от порогов отдельной записи и итогового JSON: раньше они имели один код. Успех третьей попытки не доказывает, какой именно предел остановил вторую.

Ручная сверка 18 контрольных тем показала улучшения отдельных привязок обработки и допусков, разделение двух отверстий и появление IT. Вместе с тем остались неверные границы размера, непонятые поперечные размеры паза, неполный перечень поверхностей и пустые размерные цепи; часть верных связей модель считает спорными. Общая точность не оценивалась: этот же чертёж использован при настройке, отложенной выборки нет. Выход не готов к автоматическому CAD.

После третьего запроса исправлено ложное предупреждение о конфликте расстояний от общего торца. Итоговый JSON перепроверен локально, факты модели не менялись. Успешно прошли 42 автоматических Rust-теста (4 специальных теста исключены из обычного запуска), отдельная перепроверка сохранённого JSON, 4 теста подготовки PDF, сборка и проверка интерфейса с подменённым API. Установленная Windows-версия проверяется отдельно: полный актуальный промпт, параметры high/50 000, повторное открытие окна и отсутствие ошибок JavaScript.

Локальный отчёт содержит исходный контроль 0.4.3, обе успешные попытки 0.5, ошибку второй попытки, снимки настроек и таблицу сверки. Производственные данные не входят в репозиторий.
