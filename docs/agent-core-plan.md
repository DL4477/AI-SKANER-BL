# Проект ядра агента чтения чертежей

Подготовлено 8 октября, обновлено 10 октября 2026 года. Согласовано отдельное приложение, разрабатываемое в VS Code, подключение модели через API и возможность развёртывать её локально. Предложенное направление принято как основа [плана проектирования приложения](application-design-plan.md). Окончательный выбор модели и состава инструментов зависит от испытаний на чертежах. Продуктовое ядро ещё не реализовано, испытания не проводились.

## Выбор модели

Для первого испытания с приоритетом качества предлагается **Kimi K3**. Официальная карточка подтверждает нативное понимание изображений и опубликованные веса. Это основание включить модель в испытания, а не доказательство превосходства в чтении инженерных чертежей. [Карточка Kimi K3](https://huggingface.co/moonshotai/Kimi-K3)

| Кандидат | Роль в испытаниях | Собственное развёртывание |
| --- | --- | --- |
| Kimi K3 | Основной кандидат для сложной интерпретации через API. | Флагман серверного масштаба; опубликованные веса не означают пригодность для обычного ПК. |
| GLM-5.3-Flash | Альтернатива для сравнения качества, времени и стоимости обработки. | Мультимодальная модель с 320 млрд общих и 18 млрд активных параметров, опубликованными весами и серверными средствами развёртывания. |
| Qwen3.8-27B | Кандидат для более доступного локального режима и обязательного сравнения на тех же чертежах. | Модель с 27 млрд параметров и пониманием изображений; конфигурация памяти, точность весов и скорость проверяются на выбранном оборудовании. |

Источники для характеристик альтернатив: [GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash), [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B). Активное число параметров MoE характеризует вычисления на токен и само по себе не определяет объём памяти для всех весов.

Официальный API Kimi K3 использует идентификатор `kimi-k3`, поддерживает изображения, вызовы инструментов и структурированный ответ `json_schema` с `strict: true`. Поддержку этих возможностей у конкретного собственного сервера необходимо проверить отдельно. [Руководство API Kimi K3](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart)

Развёртывание Kimi K3 документировано для vLLM и других движков. В рецепте vLLM указаны веса порядка 1,56 ТБ и конфигурации с несколькими серверными ускорителями. Это иллюстрация масштаба, а не рассчитанная минимальная конфигурация проекта. [Рецепт развёртывания vLLM](https://recipes.vllm.ai/moonshotai/Kimi-K3)

В карточке Qwen3.8-27B размещены инструкции собственного API-сервера, но официальный управляемый сервис описан как coming soon. Его доступность нельзя считать подтверждённой только по названию модели. Для начального профиля Qwen предполагается собственный сервер или отдельно проверенный поставщик API.

Окончательный выбор определяется качеством извлечения размеров, поверхностей и технических требований на наших PDF. Общие рейтинги и результаты производителей служат для отбора кандидатов. Ни один из рассмотренных источников не подтверждает безошибочное восстановление всех поверхностей из произвольного чертежа.

## Устройство приложения

Предлагается разделить систему на пять частей:

| Часть | Назначение |
| --- | --- |
| Интерфейс | Загрузка PDF, просмотр листов и выделенных областей, управление запуском, просмотр результата и исправления пользователя. |
| Управляющее ядро | Последовательность разбора, рабочее состояние, запросы к модели, выполнение разрешённых инструментов и повторные проверки. |
| Подключение модели | Профили поставщиков и собственных серверов, подготовка сообщений, обработка ответов и отличий API. |
| Инструменты | Обработка PDF, увеличение фрагментов, OCR, извлечение геометрических сведений и проверки. |
| Хранилище проекта | Исходный PDF, фрагменты, ссылки на источники, версии результата, журнал действий и итоговый JSON. |

Рабочая основа проектирования: Python для ядра и обработки документов; FastAPI для связи интерфейса с ядром; React и TypeScript для интерфейса; Tauri для отдельного настольного окна. Python-процесс упаковывается как вспомогательный процесс приложения. Основания: [FastAPI](https://fastapi.tiangolo.com/), [вспомогательные процессы Tauri](https://v2.tauri.app/develop/sidecar/). Совместимость и упаковку проверяем ранним прототипом; этапы и критерии приведены в плане проектирования.

Модель работает в отдельном API-сервисе. Для локального режима можно подключать совместимый сервер, например LM Studio для поддерживаемых им моделей или vLLM для серверного развёртывания. Своё приложение отвечает за специализированный процесс разбора чертежей. LM Studio документирует локальный сервер и вызовы инструментов: [локальный API](https://lmstudio.ai/docs/developer/core/server), [инструменты](https://lmstudio.ai/docs/developer/openai-compat/tools).

## Профиль подключения

Профиль хранит адрес сервера, точное имя модели, ссылку на локально сохранённый ключ, режим обработки изображений, доступные вызовы инструментов, поддержку JSON Schema, лимиты контекста, времени и числа шагов. Ключ не попадает в итоговый JSON или журнал проекта.

Одинаковый формат HTTP-запросов не гарантирует одинаковую поддержку возможностей. При подключении проверяются текстовый ответ, изображение, вызов нашего инструмента и ответ по тестовой схеме. Если сервер не поддерживает строгую генерацию по схеме, результат проходит локальную проверку и ограниченное число исправлений; невалидный результат не считается готовым.

Замена API-профиля не меняет контракт `drawing_general` и `surfaces`. Переход с Kimi K3 на Qwen3.8-27B означает смену модели и требует повторной оценки качества. Самостоятельный запуск тех же весов также требует проверки точности, конфигурации и совместимости API.

## Инструменты первой версии

| Инструмент | Результат |
| --- | --- |
| Осмотр PDF | Страницы, размеры листов, наличие текстового и векторного содержимого. |
| Отрисовка листа | Изображение страницы с известным масштабом и преобразованием координат. |
| Выделение фрагмента | Увеличенная область листа с сохранением связи с исходными координатами. |
| Извлечение текста и векторных элементов | Надписи и линии, если они присутствуют в PDF; их принадлежность размерам или контурам ещё подлежит интерпретации. |
| OCR области | Текст, обозначения и координаты на сканах или в трудночитаемых фрагментах. |
| Проверка результата | Соответствие JSON Schema, существование ссылок, согласованность единиц, размеров, требований и статусов готовности. |

Каждый инструмент имеет имя, описание, схему входа, схему результата и ограниченную область действия в проекте. Модель запрашивает инструмент, ядро проверяет аргументы, исполняет запрос и возвращает результат модели. Пользователь видит вызов, входные данные, результат и ошибку, если она возникла. Сам факт наличия инструмента не означает, что модель успешно им воспользовалась.

На первом этапе достаточно собственных функций ядра с единым реестром. Для внешних инструментов можно добавить адаптер MCP, сохранив те же проверки входных данных и журнал. Свободное исполнение произвольного кода модели не требуется для перечисленных инструментов.

## Процесс чтения чертежа

1. Зарегистрировать PDF и получить обзор страниц, текста и графики.
2. Выделить общую информацию, виды, разрезы и конструктивные элементы.
3. Уточнять мелкие размеры и обозначения через фрагменты повышенного разрешения и OCR; не заменять размер измерением картинки без обоснования.
4. Сформировать поверхности, связи, размеры и технические требования, сохраняя основания для каждого утверждения.
5. Проверить общие указания вместе с местными требованиями, геометрическую достаточность и противоречия.
6. Сохранить JSON и список вопросов. При недостатке данных результат остаётся неполным; догадки не становятся подтверждёнными размерами.

Для первого агента «готовность к построению» означает проверенную достаточность описания в пределах возможностей проверяющих инструментов. Окончательная проверка корректного замкнутого тела потребует CAD-построения на следующем этапе.

## Рабочий экран

Слева — исходный PDF с выбором страницы, масштабированием и выделением областей. Справа — общая информация и дерево поверхностей с размерами и требованиями. Выбор извлечённого значения подсвечивает его источник на чертеже. Отдельно доступны журнал инструментов, вопросы и ошибки проверки, настройка модели и экспорт JSON. Пользователь может остановить разбор, исправить значение и повторно проверить результат.

## Как подтвердить выбор модели

Первый сравнительный набор — 10–20 согласованных чертежей с эталонными поверхностями, размерами и требованиями. Включить векторные PDF и сканы, разрезы, отверстия, резьбы, общие указания, местные исключения и заведомо недостаточные данные.

Для каждой модели проверять полноту поверхностей, точность чисел и единиц, правильность привязки требований, ссылки на источник, число выдуманных значений и корректное признание недостаточности данных. Отдельно измерять валидность JSON, успешность инструментов, время и стоимость обработки. Использовать одинаковый процесс и сохранять точное имя модели, настройки и разрешение изображений.

Следующий практический этап — небольшой прототип подключения API и инструментов на одном реальном PDF с ручной проверкой результата. Установка весов, выбор собственного сервера и окончательное утверждение модели выполняются после такого испытания.
