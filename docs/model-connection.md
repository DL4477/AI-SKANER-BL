# Подключение Kimi в приложении

Версия 0.2 от 10 октября 2026 года добавляет внешний Kimi API в установленное Windows-приложение. Она проверяет подключение и отдельные возможности модели. Распознавание чертежей, вызовы инструментов, производственная JSON Schema и экспорт ещё не реализованы.

## Как подключить

1. Получить API-ключ в кабинете Kimi. Для генерации нужен положительный баланс и доступ к модели.
2. В приложении открыть «Модель и инструменты», вставить ключ и нажать «Сохранить ключ».
3. Проверить доступ, затем по отдельности текст, изображение и JSON. Каждая генерация запускает один запрос; автоматических повторов нет.

Клиент использует `https://api.moonshot.ai/v1`, модель `kimi-k3`, `reasoning_effort: low`, `max_tokens: 2048`, без потока. Проверка изображений отправляет встроенную картинку с тремя синими квадратами. JSON-проверка запрашивает `{"status":"ready"}` с `response_format.type: json_schema` и `strict: true`, затем проверяет содержимое локально. Параметры соответствуют [официальному руководству Kimi K3](https://platform.kimi.ai/docs/guide/kimi-k3-quickstart).

«Ключ сохранён» означает только наличие записи на компьютере. «API Kimi доступен» подтверждает ответ `/models` и наличие модели в списке. «Kimi отвечает» появляется после правильного ответа хотя бы на одну проверку генерации. Результат каждой возможности виден отдельно; ошибка любой проверки сохраняет отметку «Проверьте Kimi». Проверки не доказывают качество распознавания чертежей.

## Границы модулей

| Модуль | Ответственность |
| --- | --- |
| `src/ui/src/model/connection.ts` | Типы и вызовы пяти команд Tauri. |
| `src/ui/src/model/useModelConnection.ts` | Загрузка состояния, сохранение, проверки, отмена, ограниченный журнал сеанса. |
| `src/ui/src/model/ModelSettings.tsx` | Поле ключа и отдельные результаты четырёх проверок. |
| `src-tauri/src/ai/mod.rs` | Команды, единственная активная проверка, защита от смены ключа во время запроса и отмена по ID. |
| `src-tauri/src/ai/vault.rs` | Windows Credential Manager через keyring v1; чтение, запись и удаление. |
| `src-tauri/src/ai/kimi.rs` | Ограниченный клиент Kimi, подготовка учебных запросов, проверка ответов и преобразование ошибок. |

Команды: `model_status`, `save_api_key`, `remove_api_key`, `run_diagnostic`, `cancel_diagnostic`. Они разрешены только основному локальному окну через Tauri capabilities. Интерфейс не может передать произвольный адрес, заголовок или тело HTTP-запроса. Удалённым страницам эти разрешения не выдаются; запросы идут из Rust. Браузерный предпросмотр не имеет подключения.

Сейчас нет отдельного Python-процесса или HTTP-сервера приложения. Планируемые обработка PDF, инструменты и цикл агента будут отдельным слоем; способ взаимодействия с ним уточняется на следующем этапе. Фиксированный профиль Kimi не является готовым адаптером для локального сервера.

## Ключ и данные

Ключ хранится в записи Windows Credential Manager: service `io.github.dl4477.ai-skaner`, user `kimi-api-key`. Это защита средствами текущей учётной записи Windows, а не изоляция от всех программ того же пользователя. Интерфейс получает только признак наличия ключа; введённое значение очищается после успешного сохранения и при закрытии настроек. В журнале, `.env`, файлах проекта и настройках браузера ключ не сохраняется. В Rust временная строка ключа очищается через `Zeroizing`; это не обещание отсутствия временных копий во всех библиотеках и памяти WebView.

Запуск приложения и сохранение ключа не отправляют запросов к Kimi. Проверки передают только фиксированные учебные данные; открытый PDF и его имя не входят в запросы. Ключ сохраняется после закрытия приложения. «Удалить ключ» удаляет локальную запись, но не отзывает ключ в кабинете Kimi. При необходимости удалить запись следует перед удалением самого приложения.

## Ограничения запросов и ошибки

Ожидание всего ответа ограничено 90 секундами, соединение — 10 секундами, тело ответа — 1 МиБ. Перенаправления и автоматические повторы отключены. Одновременно выполняется одна проверка. Отмена прекращает локальное ожидание и освобождает возможность следующей проверки; обработка и списание на стороне сервиса могут продолжаться.

Ошибки имеют код и заранее заданное сообщение: ключ не принят, отказ доступа, баланс/квота, недоступность сервиса, сеть, тайм-аут, слишком большой или некорректный ответ, несоответствие учебной проверке, ошибка хранилища, отмена. Тела ошибок сервиса, ключ и внутренние рассуждения модели интерфейсу не возвращаются. Лимит генерации и валидный JSON с неверными полями считаются неуспешными проверками.

## Проверка реализации

```powershell
pnpm install --frozen-lockfile
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml --lib --release --locked
cargo test --manifest-path src-tauri/Cargo.toml --lib --release windows_credential_store_roundtrip -- --ignored
pnpm desktop:build
```

14 автоматических тестов проверяют HTTP через локальный тестовый сервер, заголовок авторизации, параметры запроса, разбор результата, ошибки, перенаправления, размер ответа, тайм-аут, отмену, блокировку параллельных действий и жизненный цикл ключа в памяти. Отдельный явно запускаемый тест проверяет реальную запись, чтение и удаление синтетического значения в отдельной записи Windows Credential Manager. Эти проверки не используют рабочий API-ключ и не обращаются к Kimi.

Все 14 тестов и отдельный тест Windows пройдены. Проверены TypeScript, сборка release и установщика, обновление установленного приложения до 0.2.0. В установленной версии проверены чтение состояния через Tauri, окно настроек, блокировка проверок при отсутствии ключа, скрытие введённого значения и сообщение внутреннего модуля на попытку сохранить короткое тестовое значение. Рабочие ключи при этой проверке не вводились.

Проверка с настоящим аккаунтом Kimi выполняется пользователем после ввода ключа. До неё доступность модели, баланс и ответы сервиса для этого аккаунта не подтверждены.
